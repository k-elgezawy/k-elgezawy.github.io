مزامنة ترجمات Oracle APEX مع مراجعة مراحل Seed وPublish

English version

My LinkedIn post explored using APEX Automations to keep translations synchronized during development. A repeatable workflow has three stages: collect changed text, review the translated strings, and publish the updated language version.

Prepare an application-based translation

For an application using the Application-Based translation method, define its target language mapping in Shared Components → Globalization → Application Translations. The mapping and workspace context need to exist before using the APIs below. Oracle documents the complete translation workflow. Application-based translations

Use the development application ID and language code that you have selected. The ID 12345 and language ar in these examples are illustrative. Execute each stage separately in the correct APEX workspace context.

Seed the changed text

Seeding updates the translation repository with translatable strings from the primary application. After a page title, item label, or other translatable component changes, seed the relevant language mapping.

begin
    apex_lang.seed_translations(
        p_application_id => 12345,
        p_language       => 'ar'
    );
    commit;
end;

Export the changed strings to XLIFF, update the target translations, and apply the reviewed file. Existing translation work and newly introduced strings need review before publishing. The API reference describes the repository synchronization performed by this call. SEED_TRANSLATIONS

Publish the reviewed language version

After applying the translation changes, publish the same primary application and language mapping.

begin
    apex_lang.publish_application(
        p_application_id => 12345,
        p_language       => 'ar'
    );
    commit;
end;

Publishing builds the underlying translated application by combining the primary application's definition with the repository's translated strings. Run the application in the target language and inspect the changed pages. PUBLISH_APPLICATION

Automate the development preparation

An APEX Automation can run a seeding action after your development workflow identifies an approved change. Keep the application and language explicit, restrict who can initiate synchronization, and record the stage, start time, duration, and outcome. Use the Automation Execution Log to inspect failures. Test an on-demand run before enabling a schedule. Creating an Automation

Keep publishing behind a separate reviewed release action. For the acceptance check, change one label, seed it, apply its translation, publish, and confirm that the target-language page displays the expected text. Also check an untranslated string, the selected language, and Arabic direction when Arabic is the target.

النسخة العربية

بوستي على LinkedIn كان عن استخدام APEX Automations للحفاظ على تزامن الترجمات أثناء التطوير. مسار العمل القابل للتكرار له ثلاث مراحل: تجميع النصوص المتغيرة، ومراجعة الترجمة، ونشر نسخة اللغة بعد تحديثها.

جهّز ترجمة التطبيق

للتطبيق الذي يستخدم طريقة Application-Based، عرّف ربط اللغة المطلوبة من Shared Components → Globalization → Application Translations. الربط وسياق الـWorkspace لازم يكونوا موجودين قبل استخدام الـAPIs التالية. توضح Oracle مسار الترجمة كاملًا. ترجمة التطبيق

استخدم معرّف تطبيق التطوير وكود اللغة اللذين اخترتهما. المعرّف 12345 واللغة ar في الأمثلة للتوضيح. نفّذ كل مرحلة بشكل مستقل داخل سياق الـWorkspace الصحيح.

اجمع النصوص المتغيرة

عملية Seeding تحدّث مستودع الترجمة بالنصوص القابلة للترجمة من التطبيق الأساسي. بعد تغيير عنوان صفحة أو اسم عنصر أو مكوّن آخر قابل للترجمة، شغّلها لربط اللغة المطلوب.

begin
    apex_lang.seed_translations(
        p_application_id => 12345,
        p_language       => 'ar'
    );
    commit;
end;

صدّر النصوص المتغيرة إلى XLIFF، وحدّث النصوص المترجمة، وطبّق الملف بعد مراجعته. راجع عمل الترجمة الموجود والنصوص الجديدة قبل النشر. يوضّح مرجع الـAPI كيفية مزامنة المستودع التي ينفذها الاستدعاء. SEED_TRANSLATIONS

انشر نسخة اللغة بعد المراجعة

بعد تطبيق تغييرات الترجمة، انشر التطبيق الأساسي نفسه مع ربط اللغة المطلوب.

begin
    apex_lang.publish_application(
        p_application_id => 12345,
        p_language       => 'ar'
    );
    commit;
end;

النشر يبني نسخة التطبيق المترجمة بدمج تعريف التطبيق الأساسي مع النصوص المترجمة في المستودع. شغّل التطبيق باللغة المستهدفة وراجع الصفحات المتغيرة. PUBLISH_APPLICATION

أتمت تجهيز الترجمة في التطوير

APEX Automation تقدر تشغّل إجراء Seeding بعد أن يحدّد مسار التطوير تغييرًا معتمدًا للمزامنة. حدّد التطبيق واللغة بوضوح، واضبط صلاحية تشغيل المزامنة، وسجّل المرحلة ووقت البداية والمدة والنتيجة. استخدم Automation Execution Log لفحص الأخطاء. اختبر التشغيل عند الطلب قبل تفعيل الجدول. إنشاء Automation

اربط النشر بإجراء إصدار منفصل بعد المراجعة. لاختبار القبول، غيّر اسم عنصر واحد، وشغّل Seeding، وطبّق ترجمته، ثم انشر وتأكد من ظهور النص المتوقع في صفحة اللغة المستهدفة. راجع أيضًا نصًا لم يُترجم، واللغة المحددة، واتجاه الواجهة عند استهداف العربية.
