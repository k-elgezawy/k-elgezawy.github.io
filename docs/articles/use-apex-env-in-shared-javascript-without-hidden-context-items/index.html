استخدام apex.env في JavaScript المشترك بدون عناصر مخفية لتكرار السياق

English version

A shared JavaScript file often needs to know which APEX page is running or where an application image lives. Creating hidden items just to repeat that framework context adds another set of values to maintain.

My original LinkedIn post introduced apex.env. This walkthrough turns that idea into a small shared helper with explicit initialization, predictable types, and a clear boundary between browser behaviour and server decisions.

Read the context with its documented types

Oracle documents APP_ID, APP_PAGE_ID, and APP_FILES as strings in apex.env. The object has been available since APEX 21.2; the reference linked here describes 26.2. Check the documentation matching your deployed version. Oracle JavaScript API

For a focused development check on an APEX application page, inspect only the values you need:

console.table({
    pageId: apex.env.APP_PAGE_ID,
    pageIdType: typeof apex.env.APP_PAGE_ID,
    filesBase: apex.env.APP_FILES
});

On page 10, expect pageId to be the string "10" and pageIdType to be "string". The asset path depends on the application. A strict comparison with the number 10 therefore fails; compare with "10" deliberately. Avoid copying a full environment dump into support tickets or shared logs, especially session identifiers and user information.

Build a small shared helper

In a development application, upload an illustrative company-logo.svg to Static Application Files. Add this markup to a Static Content region on a test page:



<p id="page-context"></p>


<img id="company-logo" alt="Company logo" width="120" height="40">


<p id="dashboard-help" hidden>Dashboard-specific help.</p>

Create page-context-demo.js with the following content:

window.kgPageContextDemo = (function () {
    "use strict";

    function init() {
        const env = apex.env;
        const badge = document.getElementById("page-context");
        const logo = document.getElementById("company-logo");
        const help = document.getElementById("dashboard-help");

        if (badge) {
            badge.textContent =
                "App " + env.APP_ID + " / Page " + env.APP_PAGE_ID;
        }
        if (logo) {
            logo.src = env.APP_FILES + "company-logo.svg";
        }
        if (help) {
            help.hidden = env.APP_PAGE_ID !== "10";
        }
    }

    return { init: init };
}());

The checks for missing elements let another page load the same file without needing the demonstration region. The helper writes plain text through textContent, so it does not interpret the badge value as HTML. MDN: textContent

The file reads the current context when init runs. It constructs the image path from APEX's application-file prefix, rather than embedding a workspace-specific path. Keep the file name aligned with the uploaded asset and verify the resulting request in the browser's Network panel.

Load the file, then initialize the page

Upload the JavaScript file to Static Application Files and use its displayed Reference URL. In the test page's JavaScript File URLs, that reference can be:

#APP_FILES#page-context-demo.js

To share it application-wide, use the JavaScript File URLs setting in User Interface Attributes. Copy the Reference value that APEX supplies, including any relevant minification substitution, and avoid including the same file both globally and again on the page. Oracle: shared helper files

In the test page's Execute When Page Loads attribute, call:

window.kgPageContextDemo.init();

Oracle distinguishes loading JavaScript files, declaring functions, and executing page-load code. Calling the helper after the page is initialized keeps DOM access out of the file's top-level loading phase. Page JavaScript attributes

Verify the behaviour and its limits

On page 10, the badge should identify the current application and page, the image should load, and the help text should appear. On another test page, the help should remain hidden. On a page without the region, the element checks should avoid missing-element errors.

If a partial refresh replaces this region's DOM, call the helper again from the relevant refresh handling; the original page-load call does not initialize newly replaced elements. This helper adds no event listeners, so repeating its assignments does not stack handlers.

Use this context for presentation and asset references. Browser values and visibility choices are not permission checks; validate protected operations and data access on the server. Keep genuine business items when they represent input or server-side state. These examples show an expected integration pattern, not a claim that code was executed against your application.

النسخة العربية

ملف JavaScript المشترك بين صفحات APEX غالبًا يحتاج يعرف الصفحة الحالية أو مكان صورة خاصة بالتطبيق. إنشاء عناصر مخفية لمجرد تكرار معلومات السياق التي يوفرها الإطار يضيف قيمًا أخرى تحتاج صيانة.

في البوست الأصلي على LinkedIn، عرضت apex.env. الشرح التالي يحوّل الفكرة إلى Helper مشتركة صغيرة، مع تهيئة صريحة وأنواع بيانات واضحة وفصل بين سلوك المتصفح والقرارات التي ينفّذها السيرفر.

اقرأ السياق بأنواع البيانات الموثّقة

توثّق Oracle الخصائص APP_ID وAPP_PAGE_ID وAPP_FILES كنصوص داخل apex.env. الكائن متاح من APEX 21.2؛ والمرجع المرتبط هنا يصف 26.2. راجع التوثيق المناسب للإصدار الذي تشغّله. Oracle JavaScript API

لفحص محدد أثناء التطوير داخل صفحة تطبيق APEX، اعرض القيم التي تحتاجها فقط:

console.table({
    pageId: apex.env.APP_PAGE_ID,
    pageIdType: typeof apex.env.APP_PAGE_ID,
    filesBase: apex.env.APP_FILES
});

في الصفحة 10، القيمة المتوقعة لـpageId هي النص "10"، ولـpageIdType هي "string". ومسار الملفات يتحدد حسب التطبيق. لذلك المقارنة الصارمة مع الرقم 10 تفشل؛ قارِن مع النص "10" بشكل مقصود. تجنّب نسخ الكائن كاملًا إلى تذاكر الدعم أو السجلات المشتركة، خصوصًا معرّفات الجلسات ومعلومات المستخدمين.

ابنِ Helper مشتركة صغيرة

داخل تطبيق تطوير، ارفع صورة توضيحية باسم company-logo.svg إلى Static Application Files. أضف الكود التالي إلى Static Content region في صفحة اختبار:



<p id="page-context"></p>


<img id="company-logo" alt="Company logo" width="120" height="40">


<p id="dashboard-help" hidden>Dashboard-specific help.</p>

أنشئ ملف page-context-demo.js بالمحتوى التالي:

window.kgPageContextDemo = (function () {
    "use strict";

    function init() {
        const env = apex.env;
        const badge = document.getElementById("page-context");
        const logo = document.getElementById("company-logo");
        const help = document.getElementById("dashboard-help");

        if (badge) {
            badge.textContent =
                "App " + env.APP_ID + " / Page " + env.APP_PAGE_ID;
        }
        if (logo) {
            logo.src = env.APP_FILES + "company-logo.svg";
        }
        if (help) {
            help.hidden = env.APP_PAGE_ID !== "10";
        }
    }

    return { init: init };
}());

فحص وجود العناصر يسمح لصفحة أخرى بتحميل نفس الملف بدون احتياجها لمنطقة المثال. وتكتب الـHelper النص باستخدام textContent، وبالتالي لا تفسّر قيمة الشارة باعتبارها HTML. MDN: textContent

يقرأ الملف السياق الحالي عند تشغيل init. ويبني مسار الصورة من بادئة ملفات التطبيق التي توفرها APEX، بدل كتابة مسار خاص بمساحة عمل معينة. طابق اسم الملف مع الصورة المرفوعة، وتحقّق من طلب تحميلها في Network panel داخل المتصفح.

حمّل الملف ثم هيّئ الصفحة

ارفع ملف JavaScript إلى Static Application Files واستخدم Reference URL الظاهر له. في JavaScript File URLs لصفحة الاختبار، يمكن أن تكون الإشارة:

#APP_FILES#page-context-demo.js

ولمشاركته على مستوى التطبيق، استخدم JavaScript File URLs داخل User Interface Attributes. انسخ Reference الذي توفره APEX، بما فيه أي صيغة مناسبة لتحميل النسخة المصغّرة، وتجنّب تحميل نفس الملف مرة على مستوى التطبيق ومرة أخرى في الصفحة. Oracle: ملفات الـHelpers المشتركة

في خاصية Execute When Page Loads بصفحة الاختبار، استدعِ:

window.kgPageContextDemo.init();

تفرّق Oracle بين تحميل ملفات JavaScript وتعريف الدوال وتنفيذ كود عند تحميل الصفحة. استدعاء الـHelper بعد تهيئة الصفحة يفصل التعامل مع DOM عن لحظة تحميل الملف نفسه. خصائص JavaScript للصفحة

تحقّق من السلوك وحدوده

في الصفحة 10، المفروض الشارة تعرض التطبيق والصفحة الحاليين، والصورة تتحمّل، ونص المساعدة يظهر. وفي صفحة اختبار أخرى، يفضل نص المساعدة مخفيًا. وفي صفحة بدون منطقة المثال، فحص العناصر المفروض يتجنب أخطاء الوصول لعناصر غير موجودة.

لو تحديث جزئي استبدل DOM الخاص بالمنطقة، استدعِ الـHelper مرة أخرى من معالجة التحديث المناسبة؛ استدعاء تحميل الصفحة الأصلي لا يهيّئ العناصر التي أُنشئت بدل القديمة. الـHelper دي لا تضيف Event Listeners، لذلك تكرار تعيين القيم لا يراكم Handlers.

استخدم السياق للعرض ومسارات الملفات. قيم المتصفح وإخفاء العناصر مش فحص صلاحيات؛ تحقّق من العمليات المحمية والوصول للبيانات على السيرفر. واحتفظ بعناصر العمل الحقيقية عندما تمثّل مدخلات أو حالة على السيرفر. الأمثلة بتوضح نمط تكامل وسلوكًا متوقعًا، ولا تدّعي تنفيذ الكود على تطبيقك.
