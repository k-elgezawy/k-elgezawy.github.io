SQL Developer Web وAPEX: اختيار نقطة البداية

English version

Sometimes you want to inspect tables, run SQL, or review packages without navigating through application pages. SQL Developer Web is one option provided through Oracle REST Data Services.

The shortened link in my original post resolves to Oracle's ORDS landing page. That page offers separate entry points for SQL Developer Web and APEX. They should not be confused with a universal login that accepts every workspace account.

Access depends on the environment

A direct SQL Developer Web login normally involves a database schema enabled for that service. APEX can also provide an integrated entry point through SQL Workshop when the instance and schema configuration support it. In APEX 26.2, the SQL Developer Web schema list shows the workspace schemas the developer is authorized to access.

Start from your organization's trusted APEX or ORDS address, choose the intended schema, and confirm the environment before executing SQL. A convenient editor does not change the account's privileges or make production operations safe.

For quick browsing, compare the workflow with SQL Workshop and use whichever fits the task. For repeatable changes, keep scripts in source control and follow the deployment process.

Editorial correction: a workspace name, username, and password are not a universal login recipe for every SQL Developer Web installation.

References: APEX 26.2 integration and SQL Developer Web access model.

النسخة العربية

أحيانًا تحتاج تراجع Tables أو Packages أو تشغل SQL من غير التنقل بين صفحات التطبيق. SQL Developer Web أحد الخيارات المتاحة من خلال ORDS.

الرابط المختصر في البوست الأصلي بيوصل إلى صفحة ORDS الرسمية، وفيها مداخل منفصلة لـSQL Developer Web وAPEX. دي مش شاشة دخول موحدة تقبل أي حساب Workspace.

طريقة الدخول تعتمد على البيئة

الدخول المباشر لـSQL Developer Web عادة يرتبط بحساب Schema مفعّل للخدمة. وفيه دخول متكامل من SQL Workshop لما إعدادات الـInstance والـSchema تسمح. في APEX 26.2، قائمة SQL Developer Web تعرض Schemas المرتبطة بالـWorkspace والمسموح للمطور الوصول لها.

ابدأ من عنوان APEX أو ORDS الموثوق في مؤسستك، واختار الـSchema والبيئة الصحيحة قبل تنفيذ SQL. سهولة المحرر لا تغير الصلاحيات ولا تجعل عمليات الإنتاج آمنة تلقائيًا.

للمراجعة السريعة، قارن تجربة الاستخدام مع SQL Workshop. وللتغييرات المتكررة، احفظ السكربتات في Source Control واتبع دورة النشر.

تصحيح تحريري: اسم Workspace وUsername وPassword ليسوا وصفة دخول عامة لكل تثبيت SQL Developer Web.

المراجع: تكامل APEX 26.2 ونموذج الدخول.
