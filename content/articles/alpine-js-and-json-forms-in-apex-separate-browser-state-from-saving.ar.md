في نموذج مصروفات يحتوي على بنود تنقل متكررة، Alpine.js تقدر تدير تعديل الصفوف، وAPEX تتولى المعالجة على السيرفر. المثال الأصلي استخدم Modal Dialog وStatic Content Region وP10_LINES_JSON لنقل التاريخ والوصف ونوع التنقل والتكلفة.

### زامن حالة المتصفح

داخل Alpine Component، راقب rows وحولها إلى JSON في APEX Item:

```javascript
this.$watch('rows', value => {
  apex.item('P10_LINES_JSON')
    .setValue(JSON.stringify(value));
});
```

مراقب Alpine يتابع التغييرات المتداخلة بالفعل؛ خيار `{ deep: true }` الإضافي في الوصف الأصلي غير ضروري. [توثيق $watch](https://alpinejs.dev/magics/watch).

**تصحيح تحريري:** تغيير Hidden Item لا يحفظ بيانات العمل، ولا يحدث Session State على السيرفر تلقائيًا. أرسل القيمة مع Submit أو بطلب AJAX صريح، ثم نفّذ عملية حفظ تتحقق من الصلاحيات. لا تعرض “تم الحفظ” إلا بعد نجاح العملية. [واجهة item في APEX](https://docs.oracle.com/en/database/oracle/apex/26.2/aexjs/item.html).

### تحقق قبل الحفظ

JSON_TABLE تقدر تحول JSON المرسلة إلى أعمدة علائقية. اختار معالجة أخطاء واضحة؛ تحليل JSON لا يغني عن مراجعة الحقول المطلوبة والتواريخ وأنواع التنقل المسموحة وعدم سلبية التكلفة وحجم البيانات. أعد حساب الإجماليات المعتمدة على السيرفر. [توثيق JSON_TABLE](https://docs.oracle.com/en/database/oracle/oracle-database/26/sqlrf/JSON_TABLE.html).

تحقق من ملكية الطلب وكل Line ID مرسلة، واكتشف التعديلات المتزامنة بمراجعة رقم الإصدار. احفظ التغييرات المتحقق منها داخل الـTransaction المقصودة.

*تصحيح إضافي: استبدال كل الصفوف بأسلوب Delete ثم Insert ليس طريقة آمنة عامة لمنع التكرار. ممكن يؤثر على المعرّفات والعلاقات وسجل التدقيق والتعديلات المتزامنة. اختار قواعد الحفظ المناسبة لنموذج البيانات الفعلي.*

Interactive Grid تظل اختيارًا صالحًا. الفورم المخصصة تستحق الكود الإضافي لما طريقة التفاعل المطلوبة تبرر ذلك.
