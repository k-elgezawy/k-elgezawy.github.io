Session State مفيدة كسياق للتطبيق، لكنها مش طبقة حماية تلقائية لكل REST API التطبيق بيتعامل معها.

**تصحيح للبوست الأصلي:** تخزين ADMIN في P0_USER_ROLE وربطه بـAuthorization Scheme لا يحمي ORDS Endpoint مستقلة تلقائيًا.

### احمِ كل مدخل على حدة

في صفحة APEX أو Callback، طبّق الصلاحيات على السيرفر وراجع السجلات المطلوبة. استخرج الأدوار من مصدر موثوق؛ قيمة Role يقدر المتصفح يرسلها لا يصح تكون مصدر القرار الأمني.

في ORDS API، جهّز المصادقة والصلاحيات الخاصة بالخدمة، مثل Privileges وRoles المناسبة، وطبّق صلاحيات السجلات داخل التنفيذ. اللي يستدعي الخدمة مباشرة لازم يمر بنفس حدود الوصول.

### هوية المستأجر لازم تكون موثوقة

عزل العملاء يحتاج Tenant Identity متحققًا منها، وفلاتر أو سياسات قاعدة بيانات متسقة في كل المسارات. شرط على الراتب داخل تقرير واحد ليس تصميمًا عامًا لعزل العملاء.

اختبر مستخدمًا مصرحًا له، ومستخدمًا بدور مختلف، ومستخدمًا من عميل آخر، وطلبًا بدون تسجيل دخول. اختبر الاستدعاءات المباشرة أيضًا، مش مجرد الأزرار.

Authorization Schemes قوية في الأماكن اللي بتُطبق فيها، ولا تمتد تلقائيًا إلى خدمات مستقلة.
